# AA Rent A Car — Plan #7: Payments Implementation Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans.

**Goal:** Customers pay via Stripe (cards + Apple/Google Pay), Tabby BNPL, Cash on Delivery, or Bank Transfer. The booking status machine wires up correctly: paid online → `pending_approval`; offline (COD/Bank Transfer) → `pending_payment` until manager confirms. Deposit holds via Stripe manual-capture intents are placed at booking time on card payments. Refunds flow per method. **After this plan ships:** a real customer can complete a booking with money actually changing hands.

**Architecture:** Adds `payments`, `payment_holds`, `refunds` schemas. Stripe + Tabby SDKs. Webhook handlers at `/api/webhooks/stripe` and `/api/webhooks/tabby` — signature-verified, idempotent via event ID dedupe in a `webhook_events` table. Provider keys are sourced from `provider_credentials` table (Plan #9) with env fallback for bootstrap. Cancellation policy is a settings-driven function.

**Spec reference:** §6.5 payments + payment_holds + refunds, §10 payments + deposits.

## Task 4: Stripe webhook handler
```ts
// /api/webhooks/stripe/route.ts
export async function POST(req: Request) {
  const sig = req.headers.get('stripe-signature') ?? '';
  const body = await req.text();
  const event = stripe.webhooks.constructEvent(body, sig, getProviderCredential('stripe','webhook_secret'));
  // Idempotency
  const dup = await db.select().from(webhookEvents).where(eq(webhookEvents.id, `stripe:${event.id}`)).limit(1);
  if (dup.length > 0) return new Response('ok', { status: 200 });
  await db.insert(webhookEvents).values({ id: `stripe:${event.id}` });

  if (event.type === 'payment_intent.succeeded') { /* mark payment succeeded, booking -> pending_approval */ }
  if (event.type === 'payment_intent.payment_failed') { /* mark failed, booking stays pending_payment */ }
  if (event.type === 'charge.refunded') { /* update refund row */ }
  return new Response('ok', { status: 200 });
}
```

## Task 6: Customer checkout UI
- After booking creation lands at `pending_payment`, customer is sent to `/my-bookings/[code]/checkout`.
- PaymentMethodPicker: 4 tiles. Each tile shows: cost preview + UAE-relevant notes.
- Stripe Elements (card method): mounts `<PaymentElement/>`, submits to `confirmPayment` server action returning the client secret.
- Tabby: server action returns the redirect URL → window.location.
- COD: confirms intent, booking stays `pending_payment → pending_approval` (manager approves first, driver collects on handover).
- Bank Transfer: shows bank details (env-configured initially; manager-configurable in Plan #10), customer types reference number, marks "I will transfer" → status `pending_payment` with `payments.method='bank_transfer'`, manager manually confirms in Plan #10.

## Task 7: Deposit handling
- For card payments: at booking confirmation, create a SEPARATE PaymentIntent with `capture_method='manual'` for the deposit amount (category default or override).
- Insert `payment_holds` row with status `held` + intent id.
- pg-boss job (stub for Plan #11) auto-releases 1 hour after handover return inspection clears.
- Manager-triggered capture: enters amount, server captures the hold (full or partial), releases remainder.

## Task 8: Refunds
Manager-side button on booking detail. Refund modal: amount (default = full), reason. Calls Stripe or Tabby refund, inserts `refunds` row, updates `payments.status='refunded'`, appends `booking_event`.

## Task 9: Cancellation policy enforcement
`src/lib/payments/cancellation.ts` (pure):
```ts
export function computeRefundOnCancel(now: Date, pickupAt: Date, totalAed: number, policy: {
  freeUntilHoursBefore: number; halfUntilHoursBefore: number; noRefundUntilHandover: boolean;
}): number {
  const hoursToPickup = (pickupAt.getTime() - now.getTime()) / 3600_000;
  if (hoursToPickup > policy.freeUntilHoursBefore) return totalAed;
  if (hoursToPickup > policy.halfUntilHoursBefore) return Math.floor(totalAed / 2);
  return 0;
}
```
Test with the default 24h/2h policy from spec §10.5.
